# PDF TransNote

PDF の英文を選んで，翻訳の前に原文を直し，ローカル LLM（LM Studio など）で和訳して，ハイライトのコメントとして PDF に保存するビューアです．表示には Mozilla の [PDF.js](https://mozilla.github.io/pdf.js/) 6.5.438 を使い，Windows のデスクトップアプリ（Edge WebView2）として動きます．

画面の言語は，設定の **Display language**（表示言語）で英語と日本語から選べます（既定は英語．PDF.js の部分も含みます）．日本語の画面は，この README と同じく「ハイライト」「注釈」の言い方を使います．PDF.js の部分（例：ツールバーのハイライトの道具は「強調」）は，PDF.js の日本語の言い方のままです．訳文は設定の翻訳先の言語（既定は日本語）になります．以下では，画面の名前を英語のまま書きます．

既定では，LM Studio で動かす [PLaMo 3 翻訳モデル](https://huggingface.co/pfnet)（`plamo-3-translate-0.8b`）を使います．OpenAI 互換の API を持つほかの翻訳サービスも登録できます．

## ダウンロード

[Releases](https://github.com/mkto3510/PDFTransNote/releases) から，次のどちらかを取ってきます．

- `PdfTransNote-<版>-setup.exe`：インストーラー．管理者の権限は要りません．Windows の「設定 → アプリ」から消せるように，アンインストーラーを今のユーザーの範囲だけに登録します．新しい版は，前と同じフォルダに上書きで入れられます．
- `PdfTransNote-<版>-portable.zip`：ポータブル版．解凍するだけで使えます．レジストリは使いません．

動作環境は 64 ビット版の Windows 10・11 です．画面の表示に Microsoft Edge WebView2 ランタイムを使います（Windows 11 には標準で入っています）．

## 使い方

PDF を開く方法は三つあります．

- Zotero の「PDF 文書を開く」に指定して開く（下記）．
- `PdfTransNote.exe` に PDF をドロップする．
- アプリの「開く」（`Ctrl+O`）を使う．

### 文字を選んだとき

英文を選ぶと，その下にポップアップが出ます（下に場所がなければ上に出ます）．選べるのは最大 3 ページにまたがる範囲までです．上から順に，次のものが並びます．

| 部品 | 動き |
|---|---|
| **色の丸**（8 色） | その色でハイライトを作り，翻訳を順番待ちの列に入れます．ポップアップは閉じるので，すぐに次の文字を選べます．訳が届くとコメントに入り，PDF が保存されます． |
| 除いた部分（あるときだけ） | 本文に挟まれていたので原文から除いた部分が，「Skipped: header/footer (p. 5)」のように出ます．**Include** を押すと，この選択だけ原文に戻します． |
| **原文の欄** | 選んだ文字が出ます．ここで直した文字が翻訳に使われます．改行，行末のハイフン，ﬁ などの合字は自動で整えます．日本語の行の切れ目には空白を入れません．字下げで始まる段落の切れ目は空行で残します．文書の中にハイフン付きで書かれた語（short-wavelength など）は，行末で切れてもハイフンを残します． |
| **Translate**（`Alt+T`，欄の中では `Ctrl+Enter`） | ポップアップの中で翻訳します．訳文は直せます．**Add Annotation**（訳文の欄で `Ctrl+Enter`）か色の丸を押すと，その訳文をコメントにしたハイライトができます．翻訳中に押した場合は，ハイライトを先に作り，訳が届いたらコメントに入れます． |
| **Annotate & Translate**（`Alt+Shift+T`） | 最後に使った色で，色の丸と同じことをします． |
| サービスの切り替え | 使う翻訳サービスを選びます（設定と同じものです）． |

- 翻訳は，一つが終わるのを待たずに何件でも続けて頼めます．翻訳サーバーに同時に送る数は，設定の **Concurrent requests**（既定 2）で決まり，超えた分は順番を待ちます．
- 翻訳中のハイライトには，点線の枠が付きます．
- `Esc` か，ポップアップの外を押すと閉じます．注釈にしていない訳は残りません．
- ポップアップの右下の取っ手をドラッグすると，大きさを変えられます．大きさは覚えていて，取っ手をダブルクリックすると自動の大きさに戻ります．

#### ページをまたぐ選択と，除かれる部分

- ページをまたいで選ぶと，PDF の注釈はページごとなので，ページごとにハイライトを一つずつ作ります．どれにも同じ訳文をコメントとして入れます．
- 同じセッションの間は，これらを一つとして扱います．色の変更，削除，翻訳中の印は，すべての部分に働きます．PDF を開き直すと，それぞれ別のハイライトになります（コメントは同じ訳文です）．
- 次のものが本文に挟まれているときは，原文からもハイライトからも除きます．
  - ヘッダー，フッター，ページ番号（章ごとに変わるもの，「― 690 ―」の形，DOI の行も）
  - 図表の見出し（Figure 3:，Fig. 2.，Table 1:，図 1．，表 2：，第 1 図 など．区切りのない「Table 1 Radar …」も，すぐ前後が表や図なら見出しとします）
  - 本文より小さい文字や回転した文字（脚注，表，図の中の文字）
  - 本文と同じ大きさでも，表（数字の多い欄が 3 つ以上並ぶ行，上下の罫線で挟まれた欄の並び），図（画像や線画）の上の文字，短い記号ばかりの小さな段落（図の中のラベル）
  - 脚注の区切りの短い横線より下の段落
  - 余白の注（本文の枠の外にある「Section 6.4」「Exercise 7.2」など）
  - 1 ページ目の下の所属・連絡先の脚注（本文より小さいもの，または「*」などで始まる 2 行までのもの．「*」「〒」「e-mail」など）
  - 別行立ての数式（式番号のある行，段の中ほどに置いた式．式の間の「where」「or」などの本文は残します）
  - アルゴリズムの箱とコードの箱（本文に挟まれているとき）．「Algorithm 1」などの見出しは図表の見出しとして，中身はコードとして，別々に扱います
  - ルビ（ふりがな）．ルビは選択の端にあっても除きます．
  - 行番号（査読用原稿などの余白の 1, 2, 3 …）．行番号は，ルビと同じく，選択の端にあっても除きます．
- 段をまたいで選んだときは，読む順（下の「仕組み」）に並べ直し，読む順で選択の初めと終わりの間にないもの（段の後に描かれた見出しなど）を除きます．段の最後まで選んだとき，段の後に描かれた式などまで選択が伸びた部分も，同じ理由で除きます．
- 選択がそのような部分から始まる，または終わるときは，その部分を残します．ただし，選択のいちばん端のヘッダー・フッターは除きます．
- 除く規則は，設定の **Selection** で切り替えられます．

仕組み：PDF を開くと，バックグラウンドで全ページを読み，PDF の文字の位置と大きさから，文字を「本文」「図表など」「ページの飾り」に分けます（画像から文字の種類を当てる学習済みのモデルは使いません）．

- ヘッダー・フッター：ページの上端・下端の帯（既定は高さの 12%）にある行が，前後 8 ページの同じ側・同じ高さに 2 ページ以上（数字は区別せず，OCR の揺れは文字の似かたで許して）出てくれば，ヘッダー・フッターとみなします．行の頭か末尾の数がページの順に 1 ずつ（見開きを 1 ページにした PDF では 2 ずつ）増える行も，ページ番号の入ったヘッダー・フッターとみなします．
- 余白の注：本文の長い行の左端・右端から，偶数・奇数ページごとに本文の枠を求め，その外にある行を余白の注とします．同じ高さでも横に大きく離れた文字は，別の行として扱います．
- 本文の大きさ：文字数で重みを付けた最頻値です．本文の段落に挟まれ，左端と幅がそろう段落は，少し小さくても本文とします（OCR で行ごとに大きさが揺れる PDF や，添え字の多い行）．
- 図：PDF.js がページを描いたときの画像の位置を覚え，その上の文字を図の中の文字とします（ページ全体を覆うスキャンの画像は除きます）．線画も，近い線・曲線・塗りをまとめて図の領域とします（PDFFigures 2.0 の考え方）．本文の長い行を 2 行以上含む領域（行の背景の色など）は図としません．
- 表：上下の罫線で挟まれ，欄に分かれた行の並びを表とします．
- 図表の見出しの続き：見出しの段落の中で，文で終わった行の後の行間が見出しの中の行間より広いか，本文のフォントに戻る行からは，次の段落とします（字下げした凡例の行は見出しの続きとします）．見出しが図に接しているか，本文と違うフォントか，本文の段の左端にそろわないときは，区切りのない「Figure 3 Map …」も見出しとします．「Figure 3 shows …」のように番号の後が小文字の語で始まる文は本文です．
- 脚注：ページの下半分の，段の左端から始まる短い横線（ほかの罫線と並ばず，すぐ上に文字がないもの）より下の段落を脚注とします．
- 別行立ての数式：配置で見分けます．行の右端の式番号（「(3)」．前に大きな空きがあるもの），または段の中で左右に空きがあって中央にそろい，前後の行との間が広い行を式とし，そのすぐ上下の字下げした行（分数の上下，複数行の式）も含めます．語の多い行，数だけの行，本文より大きい行は式としません．
- 行番号：整数だけの文字が，本文の外の余白（二段組の段の間も）で同じ位置にそろい，上から 1 ずつ（または 5 ずつ）増え，行の送りが一定なら，行番号とします．番号の少ないページでも，ほかのページで見つけた列と同じ位置なら行番号とします．表の番号の欄（上下に見出しなどの文字がある列）は取りません．
- アルゴリズム・コードの箱：語ではなく主に配置で見分けます．PDF.js がページを描いたときの箱（塗った矩形，囲んだ矩形，上下の罫線）の位置を覚え，その中で，行の右端がそろわず，右端の近くまで届く行が少なく，字下げが何段にも分かれる行の並びを，アルゴリズムやコードとします．箱がなくても，4 行以上の同じ形の行が，本文と違うフォントで組まれているか，行の頭に「1:」などの番号が並べばコードとします．等幅のフォントと「Algorithm 1」などの見出しは補助に使います．注釈（ハイライト）の矩形は数えません．枠で囲んだ本文・問題文や式はコードとしません．
- 読む順：国立国会図書館の NDLOCR の読み順推定（XY-cut）の考え方に倣い，段落の矩形を縦と横の空白で再帰的に分けて並べます．段の間の縦の空白を先に使い，段をまたぐ見出しや図があれば，その上下で横に分けます．
- ほかに，PDF にタグ付きで入っている Artifact（ページの飾りの印），ページ番号や図表の見出しの書き方も使います．

Zotero 10 の読み取りモード（Reading Mode）と NDLOCR（[ndl-lab/reading_order](https://github.com/ndl-lab/reading_order)，CC BY 4.0）は，考え方だけを取り入れ，コードは使っていません．

限界：PDF の文字の位置だけで判定するので，次のものは見分けられないことがあります．

- 線画の図の中の，本文と同じ大きさで長い文字
- OCR の文字の層で，左右の段の文字が一つの行につながっているもの
- OCR の文字の層で，式が本文の行に空きなしでつながっているもの（日本語版の Bishop など）
- 本文と同じフォントで組んだ，箱も見出しもない疑似コード
- 本文の文の途中に置いた，番号も前後の空きもない式

また，選んでいる途中は，除く部分にも PDF.js が選択の色を付けます．

### ハイライトをクリックしたとき

このセッションで作ったハイライトも，ファイルにもともとあったハイライトも，クリックすると次のポップアップが出ます．

| 部品 | 動き |
|---|---|
| **色の丸** | 今の色に印が付いています．押すと色を変えます． |
| コメント | 今のコメント（訳文など）です． |
| **原文の欄** | ハイライトの範囲の文字です．ここで直せます． |
| **Translate** | ポップアップの中で翻訳します．**Save to Comment** で，その訳文をコメントにします． |
| **Translate to Comment** | 翻訳を列に入れ，訳が届いたらコメントを置き換えて保存します．ポップアップは閉じます． |
| **Delete** | ハイライトを消します． |

- ハイライトや注釈をクリック・ダブルクリックしても，PDF.js の編集モードには入りません．PDF.js の編集の機能（コメント，強調，フリーテキスト，インク，画像）は，ツールバーのそのボタンを押したときだけ有効になります．大きさの変更などの細かい編集は，ツールバーのハイライトのボタンで編集モードにして行います．
- 使わない編集のボタンは，設定の **Editing buttons on the toolbar** で隠せます．
- 作れる注釈はハイライトだけです（PDF.js には下線の注釈を作る機能がありません）．

### 注釈の一覧（左のパネルの Annotations）

左のパネル（ツールバーの左端のボタンで開く，「Pages」「Document outline」などを選べるパネル）で **Annotations** を選ぶと，PDF のすべてのハイライトがカードで並びます（Zotero の注釈の一覧と同じ形）．パネルを開いたときのビューは，既定で Annotations です．選んだビューは，PDF ごとに次に開いたときも残ります（PDF が目次を表示するよう指定しているときは目次）．このビューを開いているときは，ハイライトを（PDF の上でもカードでも）押すと，浮かぶポップアップの代わりに，そのカードの下にポップアップと同じ部品が出ます．パネルを閉じているときは，これまでどおり浮かぶポップアップです．選んでいるカードのハイライトには，ページの上でも点線の枠が付きます（翻訳中の印と違い，明滅しません）．

| カードの部分 | 動き |
|---|---|
| 見出し（色と **Page 3** など） | 押すと，そのハイライトへ移動して，注釈のポップアップを開きます． |
| 原文 | ハイライトの範囲の文字です（3 行まで．押すと全部出ます）．まだ表示していないページのハイライトも出ます． |
| コメント | 訳文などのコメントです．押すとその場で直せます（`Ctrl+Enter` か外を押すと保存，`Esc` で取り消し）． |
| 翻訳の状態 | **Waiting**（待機中．**Cancel** で取り消し），**Translating…**（届いた訳が少しずつ出ます），**Failed**（理由が出ます．**Retry** でやり直し，**Edit** でポップアップを開いて直す）． |

- ページの上でハイライトを押すと，そのカードが選ばれます．
- 翻訳に失敗したときは，左下にも知らせが出ます．パネルが閉じていれば，開閉ボタンに赤い印が付きます．

### ハイライトの色

- 色は Zotero と同じ 8 色です（Yellow，Red，Green，Blue，Purple，Magenta，Orange，Gray）．
- 画面では，Zotero の表示と同じく，色を不透明度 0.4・乗算で重ねるので，文字は黒いまま読めます．
- ファイルには，Zotero が書くものと同じく不透明な色で保存します．Zotero で開いても同じ色として扱われます．
- ほかのアプリが不透明度（`/CA`）付きで書いたハイライトは，Zotero の取り込みと同じく，色を白に寄せてから重ねます．

### そのほか

- 訳は，ハイライトのコメントアイコンで読み返せます．標準の PDF 注釈なので，Zotero，Firefox，Acrobat でも見えます．
- ツールバーの保存のボタンは二つです．
  - **上書き保存**（フロッピーディスクの形，`Ctrl+S`）：元の PDF に保存します．保存していない変更があるときは，このボタンに赤い印が付きます．
  - **名前を付けて保存**（PDF.js の保存のボタン，`Ctrl+Shift+S`）：保存する場所と名前を選んで，注釈を入れた PDF を書き出します．その後も，開いているのは元の PDF のままです（続けて上書き保存すると元の PDF に保存します）．
  - 狭いウインドウでは，右端の「>>」のメニューに両方が出ます．
- 元のファイルは，その起動で初めて保存する前に `data\backups` に複製されます（新しいものから，設定の **Backups to keep**（既定 5）の数だけ残します）．
- 開いた後にほかのアプリが PDF を変えていた場合は，上書きしてよいかを確かめます．
- 保存していない変更や翻訳中のものがあるときは，閉じる前に確かめます．

## 設定（⚙）

Translate for Zotero の Custom GPT と同じ考え方で，OpenAI 互換の chat/completions の翻訳サービスを，名前を付けて何件でも登録できます．**Add**，**Duplicate**，**Delete** で増減し，**Use this service** で使うものを選びます．

### サービスごとの項目

| 項目 | 説明 | 既定値（PLaMo 3 Translate 0.8B） |
|---|---|---|
| Endpoint | 土台の URL を入れると `/v1/chat/completions` を付けます．`…/chat/completions` で終わる URL は，そのまま使います． | `http://localhost:1234`（LM Studio の既定） |
| API key | 任意．`Authorization: Bearer` として送ります． | 空 |
| Model | **Test Connection** で，サーバーにあるモデルを候補に出します． | `plamo-3-translate-0.8b` |
| temperature | 0〜2 | 0 |
| System prompt | system メッセージとして送ります（空なら送りません）．使える変数は `${langFrom}`，`${langTo}`． | `[plamo-translate]`↵`target_lang=${langTo}`↵`form=plain` |
| Prompt | user メッセージとして送ります．`${sourceText}`（必須），`${langFrom}`，`${langTo}` が使えます． | `${sourceText}` |
| Stream the response | 訳を少しずつ受け取ります． | オン |
| Extra parameters | JSON のオブジェクト．要求の本文に混ぜます（例：`{"max_tokens": 4096}`）．同じ名前の項目は上書きします． | 空 |

PLaMo 3 Translate では，`[plamo-translate]` から始まる指定をシステムプロンプトに入れてください．user メッセージ（プロンプト）に入れると，訳文の頭にその指定がそのまま出てくることがあります．

### 共通の項目

| 項目 | 既定値 |
|---|---|
| Source language（`${langFrom}`）・Target language（`${langTo}`） | English (en)・Japanese (ja) |
| Concurrent requests（翻訳サーバーに同時に送る数） | 2（1〜8） |
| Save the PDF after putting a translation into a comment | オン |
| Display language（表示言語） | English（English か 日本語）．PDF.js の部分も変わります．保存していない変更がなければ，保存したときにウインドウを読み込み直します．あるときは，次に PDF を開いたときに変わります． |
| Backups to keep（残すバックアップの数） | 5（0〜200）．すべての PDF を合わせた数で，0 なら取りません．数を減らすと，次の保存のときに古いものから消します． |

### 選んだ文字の項目（Selection，日本語では「選択した文字」）

選択がページの切れ目や図をまたぐとき，本文に挟まれた部分を除くかどうかを決めます（動きは「ページをまたぐ選択と，除かれる部分」を見てください）．

| 項目 | 既定値 |
|---|---|
| Skip headers, footers, and page numbers（ヘッダー・フッター・ページ番号を除く） | オン |
| Header and footer search range（ヘッダー・フッターを探す範囲．ページの上端・下端から，高さに対する割合 %） | 12（3〜25） |
| Skip figure and table captions（図表の見出しを除く） | オン |
| Skip smaller or rotated text（小さい文字や回転した文字を除く） | オン |
| Smaller by（小さい文字とみなす差．本文の文字より何 % 小さいか） | 6（2〜30） |
| Skip notes in the page margins（余白（本文の枠の外）にある注を除く） | オン |
| Skip ruby（ルビ（ふりがな）を除く） | オン |
| Skip line numbers in the margins（行番号（原稿の余白の 1, 2, 3…）を除く） | オン |
| Skip algorithm boxes and code listings（アルゴリズムとコードの箱を除く） | オン |
| Skip display equations（別行立ての数式を除く） | オン |

### ツールバーの編集のボタン（Editing buttons on the toolbar）

PDF.js の編集のボタン（Comment／コメント，Highlight／強調，Text／フリーテキスト，Draw／インク，Image／画像）のうち，ツールバーに出すものを選びます（既定はすべて出す）．隠したボタンの機能には入りません．

- 翻訳サーバーへの要求はアプリの中で中継するので，LM Studio の「Enable CORS」は要りません．API キーは，中継するときにアプリのサーバーが付けます．
- 設定ファイルの中で読めない項目は捨てて，既定値で始めます．

## Zotero から開く

Zotero の「編集 → 設定 → 一般 → リーダー」にある「PDF 文書を開く」で，`PdfTransNote.exe` を選びます．Zotero のデータベースにある注釈（Zotero の内蔵リーダーで付けたもの）は，このビューアには出ません．

## データの置き場所

`PdfTransNote.exe` の横の `data` フォルダに，次のものを置きます．

| ファイル・フォルダ | 中身 |
|---|---|
| `settings.json` | 設定（API キーを含みます） |
| `backups\` | 保存前に複製した PDF（残す数は設定で決めます） |
| `webview\` | WebView2 の表示用データ |
| `transnote.log` | 動作の記録 |

そこに書き込めないときだけ，`%LOCALAPPDATA%\PdfTransNote` を使います．

消すときは，次のようにします．

- setup.exe で入れた場合：Windows の「設定 → アプリ → インストールされているアプリ」で PDF TransNote をアンインストールします．最後に `data` フォルダ（設定とバックアップ）も消すかを尋ねます．既定は「残す」です．
- zip の場合：アプリのフォルダごと削除します．

## ソースから作る

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m tools.fetch_pdfjs
powershell -ExecutionPolicy Bypass -File build.ps1
```

- PDF.js はリポジトリに含めていません．`tools.fetch_pdfjs` が PDF.js の公式の Release から `pdfjs-<版>-dist.zip` を取ってきて，SHA-256 を確かめてから `vendor/` に展開します（`build.ps1` も，なければ取ってきます）．
- 版は `transnote/__init__.py` の `VERSION` で決まります．
- PDF の文字の分類を確かめるには，`node tools/dump-structure.mjs <PDF>` を実行します．ページごとの分類（本文・図表など・ページの飾り）が出ます．

- 出力は `release\` の zip（解凍するだけで使える）と setup.exe（Inno Setup 7 が必要）です．
- テストだけなら，`node --test tests/` と `.venv\Scripts\python -m unittest discover -s tests` を実行します．
- 開発中は `.venv\Scripts\python PdfTransNote.py <PDF>` で動かせます．
- ブラウザーで画面だけ試すときは `.venv\Scripts\python -m tools.devserver <PDF>` を使います．

## 構成

PDF.js に触れるコードは `web/pdfjs/` の `bridge.js` と `overrides.css` だけです（同じ場所の `highlight-math.mjs` と `page-structure.mjs` は PDF.js に触れない計算だけ）．独自の部分（`web/app/`）は PDF.js の名前や CSS 変数を使わず，`bridge.js` が出す API と `--tn-…` の変数だけを使います．PDF.js を更新したときに直すのは `web/pdfjs/` だけで済みます．

| パス | 役割 |
|---|---|
| `transnote/app.py` | ウインドウ（pywebview）．同時に一つだけ動かし，二つ目の起動からファイルを受け取る． |
| `transnote/server.py` | 127.0.0.1 だけで動く小さな HTTP サーバー．PDF.js の配布，PDF の読み出しと保存，設定，登録した翻訳サービスへの中継． |
| `transnote/settings.py`，`transnote/paths.py` | 設定の既定値と検査，ポータブルの置き場所． |
| `transnote/i18n.py` | サーバーとウインドウの文の日本語（エラーメッセージなど）． |
| `web/pdfjs/bridge.js` | PDF.js との境目．起動時の設定（表示言語など），選択とクリックの検出，ハイライトの作成・色・コメント・削除，ファイルにあった注釈の扱いと一覧，ハイライトの薄い表示，左のパネルの Annotations のビュー，編集のモードの切り替えの制限，画像の位置（図）の収集，選んだハイライトの点線の枠，保存（上書き・名前を付けて保存）・開く・ドロップの差し替え． |
| `web/pdfjs/highlight-math.mjs` | ハイライトの計算（不透明度を色に混ぜる，quadPoints の中の文字，並べ方）．PDF.js にも画面にも触れない． |
| `web/pdfjs/page-structure.mjs` | 文字を本文・図表など・ページの飾りに分類し，読む順（XY-cut）を求め，選択からそれらを除く．PDF.js にも画面にも触れない． |
| `web/pdfjs/page-graphics.mjs` | PDF.js がページを描いたときの画像・箱・罫線の位置を集める（図とアルゴリズム・コードの箱の判定に使う）． |
| `web/pdfjs/overrides.css` | PDF.js の見た目の値を `--tn-…` の変数に移す．PDF.js の要素に当てる見た目（ハイライトの薄さなど）． |
| `web/app/main.js` | 入口．`bridge` と独自の部品をつなぐ． |
| `web/app/popup.js` | 選択ポップアップと注釈ポップアップ． |
| `web/app/sidebar.js` | 左のパネルの Annotations のカード（翻訳の状態を含む）． |
| `web/app/settings-dialog.js` | 設定画面． |
| `web/app/i18n.mjs` | 画面の文の英語・日本語． |
| `web/app/core.mjs` | 原文の整形，chat の要求の組み立て，SSE の読み取り（画面に依存しない）． |
| `web/app/jobs.mjs` | 翻訳の順番待ちの列（同時に送る数の上限，取り消し，やり直し）と，保存をまとめる仕組み（画面に依存しない）． |
| `web/app/api.js`，`web/app/dom.js`，`web/app/app.css` | サーバーとデスクトップとのやりとり，要素を作る小道具，独自の部品の見た目． |
| `vendor/pdfjs-6.5.438-dist/` | PDF.js の公式配布物（`tools/fetch_pdfjs.py` が取ってくる．変更しない）． |
| `installer/` | Inno Setup 7 の台本． |
